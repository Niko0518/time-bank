# v9.37.0 — AI 强化：Hermes 部署到云托管（CloudBase Run）✅ 已完成

## Context（为什么做这件事）
v9.36.x 的 AI 是云函数批式（timebankAI），无长期记忆、无自进化。经与开发者对齐：
- **产品定位**：Hermes 负责"深度分析 + 报告 + 健康分析师 + 长期记忆"；逐笔实时交易保持规则化反馈（AI 不介入完成瞬间）。
- **路线**：放弃 OpenClaw 官方路线（CloudBase 集成轻量服务器对该账号 404 灰度未开放）→ 开发者拍板"不考虑资源消耗，在云托管装 Hermes"。
- **模型**：使用 CloudBase 资源点套餐抵扣（Token 资源包 2026-06 已下线），hy3 模型，零第三方 key。

## 最终架构（全部实测验证 ✅）

```
云托管 CloudBase Run 服务 timebank-hermes（v002 运行中，监听 9000）
├── Hermes Agent v0.18.2（PyPI 正式包）
│    ├── LLM: provider=custom → 云开发资源点网关(hy3) ← 服务端API Key(Bearer)
│    ├── 长期记忆: MEMORY.md/USER.md 跨会话 ✅（云容器内实测：记住"每天健身"→新会话召回）
│    └── 人格: SOUL.md「时间管家」✅
├── Node 桥（@cloudbase/node-sdk + 子账号密钥）
│    ├── report.mjs: 读 tb_transaction/tb_daily → hy3 → 写 tb_ai_messages ✅ (4s)
│    └── memory.mjs: 记忆 tar → 云存储 备份/恢复 ✅ (19.4KB)
├── server.py（标准库 HTTP 壳）
│    ├── /health ✅ | /report ✅ | /memory/backup|restore ✅
│    └── /chat 异步(jobId+轮询) ✅ 冷4min/热10s（平台网关60s超时所致）
└── runtime.env（镜像内运行时密钥）
HTTP 路由: /timebank-hermes → CBR timebank-hermes（两个访问域名）✅
```
