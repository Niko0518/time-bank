# TimeBank AI 落地方案（v9.37.0 周期）

> 状态：**待确认，尚未实施**
> 目标：让 AI 从"通用助手 + 数据复读"变成"看得出你是什么人、说得出你的模式"的管家
> 前置共识：Hermes **只关闭、不删除**；主链路回归"时光"；先做画像与本地能力

---

## 0. 设计原则

| 原则 | 含义 |
|---|---|
| 确定性优先 | 能本地算准的一律不调模型（秒回、零成本、零幻觉） |
| 按响应预算分层 | L1 本地（<50ms）→ L2 模型（1-3s）→ L3 后台（分钟级） |
| 只读不擅写 | 模型可读可建议；涉及写操作必须回显确认，删除类二次确认 |
| 可解释 / 可纠正 / 可沉默 | 每条结论有依据、能删能改、建议能关 |
| 不新增后端依赖 | 复用现有云函数 + 前端全量数据；退役容器链路 |

## 2. 画像系统重写（本方案核心）

### 2.1 为什么现在"僵硬"
画像输入全是统计总量（累计小时、30 天趋势、任务频次），模型只能产出数据报告式文字。
"看出你是什么人"的原料是**模式、语言证据、矛盾、变化**，不是总量。

### 2.2 输入清单（六类原料）

| # | 原料 | 来源 | 现状 |
|---|---|---|---|
| 1 | 行为轨迹（开工时段、连续段、中断点、恢复速度、任务切换） | 全量交易 | 只用总量，轨迹未用 |
| 2 | 任务元数据（名称、备注、类型、目标时长、习惯配置） | `tasks` | 未用（命名/备注带人格信息） |
| 3 | **语言证据**（目标、承诺、偏好、抱怨、借口） | `tb_ai_messages` 用户发言 + Hermes 记忆 | 几乎未用（最大缺口） |
| 4 | 跨维度（睡眠、屏幕时间、金融/欠款） | 睡眠/屏幕/金融模块 | 深度上下文里有，画像里没有 |
| 5 | 时间尺度变化（近 30 天 / 前 30 天 / 全期） | 全量交易 | 只做 30 天 |
| 6 | 矛盾检测（声明的 vs 行为） | 3 + 1 交叉 | 未做（最能体现"懂你"） |

### 2.3 画像结构（双层，替换现有单一 `summary`）

```js
tb_ai_brain.profile = {
  core: {                       // 稳定层：变化慢，需多次证据
    identity,                   // 一句话画像："夜型人，靠截止日期驱动，健身是情绪出口"
    patterns[],                 // 稳定模式（含证据）
    goals[],                    // 长期目标
    commitments[],              // 承诺/约定（含日期）
    preferences[],              // 偏好与厌恶
    triggers[],                 // 激励点 / 挫败点（什么情况会崩）
  },
  state: {                      // 状态层：随时更新，7 天过期
    rhythm,                     // 近期节奏（作息/专注）
    risks[],                    // 失衡风险（睡眠、欠款、习惯中断）
    highlights[],               // 最近亮点
    pendingCommitments[],       // 待兑现承诺
    updatedAt,
  },
  evidence: { /* 结论id: [{date, txId?, quote?}] */ },   // 依据索引（可解释）
  meta: { cognitionVersion, lastFullAt, lastDeltaAt, method }
}
```

### 2.4 更新机制

| 时机 | 动作 |
|---|---|
| 首次 / 用户点"重新认识我" | 全量重算（core + state） |
| 打开 App 且距上次 >12h | 增量更新（state 必更，core 有证据才更） |
| 每 30 天 | 全量重算（防止漂移） |
| **core 写入门槛** | 同一结论需 **≥2 次独立证据**（防单次异常污染人格判断） |
| **state 过期** | 7 天未更新则标记过期，不参与对话注入 |

### 2.5 生成位置（三候选）

| 候选 | 做法 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| **1 前端构建输入 + 云函数调模型** | 前端用全量数据算出结构化特征与候选结论 → 传 `timebankAI.initBrain` → 模型只做"提炼与措辞" | 无新后端；数据最全；时区正确（沿用 `handleInitBrain` 的 `data.prompt` 先例）；4000 条统计 <100ms（`buildDeepAnalysisContext` 已有先例） | 前端算力占用（可接受） | **推荐** |
| 2 云函数直接查库 | 云函数分页拉交易再算 | 前端轻 | 时区换算复杂、分页成本、上限风险 | 备选 |
| 3 Hermes 容器生成 | ingest 脚本 | 模型资源好 | 已证脆弱 | 不做 |

### 2.6 可纠正 / 可解释
- 画像页每条结论可展开看"依据"（来自哪几天、哪句话）
- 支持删除单条结论、一键重置画像
- 语言证据条目显示原文引用（"你 8/2 说过想减少熬夜"）

## 3. L1 本地数据问答（新增能力）

**动机**：这类问题本地能算准，不该花 token、更不该让模型编数字。

| 覆盖（首版 10 条） | 示例问法 | 数据来源 |
|---|---|---|
| 余额 | "我还剩多少时间" | `state.balance` |
| 今日汇总 | "今天赚了多少" | 交易流 |
| 本周/本月汇总 | "这周表现怎么样" | 交易流 |
| 单任务统计 | "健身一共练了多久" | 交易流 + `tasks` |
| 最长连胜 | "我坚持最久的是什么" | 习惯系统 |
| 最近睡眠 | "我昨天几点睡的" | 睡眠模块 |
| 屏幕时间 | "今天玩手机多久" | 屏幕时间模块 |
| 欠款 | "我还欠多少" | 金融模块 |
| 趋势对比 | "比上个月好还是差" | 交易流 |
| 今日完成清单 | "今天都干了什么" | 交易流 |

**实现要点**
- 新文件 `www/js/ai-local-qa.js`：问法正则 → 计算函数 → 模板化回答（数字格式化复用现有工具）
- 分流顺序：本地问答命中 → 直接回答；未命中 → 交给 L2（并把相关数据片段带进 prompt）
- 回答须标注口径（如"按你记录的时间算"），避免与首页数字不一致造成困惑

**验收**：本地问答结果与首页/报告页数字**逐项一致**；响应 <200ms。

## 4. L2 对话层优化

| 改动 | 现状 | 目标 |
|---|---|---|
| 注入策略 | 全量统计 3-5k token 每次都发 | **按问题类型检索注入**，控制在 1-1.5k token |
| 注入顺序 | 画像 summary + 全量数据 + 最近 10 条 | core 摘要（短）→ state 摘要 → 检索片段 → 最近对话 |
| 画像使用 | 仅 `brain.summary` | 结构化 core/state + 语言证据引用 |
| 写操作 | AI 解析后直接执行 | **回显确认**；删除类二次确认 |
| 语气 | 通用助手 | 引用用户自己的话与模式（"你上次说…"） |

**风险**：`ai-service.js` 约 2500 行，`buildChatPrompt` 改动会影响所有对话质量 → 保留旧版回退开关（设置项"深度上下文：开/关"）。

## 5. L3 后台认知与主动建议

| 项 | 设计 |
|---|---|
| 触发时机 | **用户打开 App 时检查**（不用云函数定时器；用户此刻有注意力） |
| 频率 | 默认"低"：每天最多 1 条；连续 3 次被忽略自动降频 |
| 说话门槛（须命中其一） | 破纪录 / 明显偏离常态 / 承诺到点 / 长期模式被打破 / 关键失衡（睡眠、欠款） |
| 呈现 | 首页气泡或报告区卡片：一句话 + "看依据"展开 |
| 反馈闭环 | "有用 / 没用" 两个按钮 → 调整频率与画像权重（这才是"越用越懂"） |
| 沉默开关 | 设置项"主动建议：关 / 低 / 中" |
| 禁止 | 不因"每笔新交易"就说话（免疫化根源） |
